# Development completion flow

- Shared birdman studio standards, AI harness evaluation and genre-specific asset workflows have one canonical source: https://github.com/b-w-hiroki/studio-playbook/blob/main/README.md (private; authorized GitHub access required). Do not duplicate the common standard in this public repository. If inaccessible, state that the common source was not read. This repo's current main, saved data contracts and horror-specific docs remain authoritative for game details.

- GitHub Issue/Decision/Projects source-of-truth pilot: [docs/GITHUB-WORKFLOW-PILOT.md](docs/GITHUB-WORKFLOW-PILOT.md). Shared canonical rules live at Private [studio-playbook GitHub Operating Model](https://github.com/b-w-hiroki/studio-playbook/blob/main/docs/GITHUB-OPERATING-MODEL.md); do not copy them here. Treat open Decision issues as awaiting a real decision, not agent-ready code changes. Do not assert Projects v2 visibility without authenticated verification.
- New chat entrypoint: [docs/AI-RESUME.md](docs/AI-RESUME.md). A short instruction such as 「真相ガチャ、開発再開」 means: read this file and live GitHub main/open PR/issues/comments/CI, not historical chat snapshots. The read-only resume workflow is not an AI coding worker.
- Start from the latest main and [docs/INDEX.md](docs/INDEX.md); [docs/CURRENT-SPEC.md](docs/CURRENT-SPEC.md) is the dated living snapshot and this file remains the invariant checklist. If documentation and code differ, investigate the code and update documents in the same PR.
- For any user-facing or save-impacting change, update the relevant document, tests and issue state; use [docs/DEVELOPMENT-WORKFLOW.md](docs/DEVELOPMENT-WORKFLOW.md), [docs/ASSET-PRODUCTION-WORKFLOW.md](docs/ASSET-PRODUCTION-WORKFLOW.md), and [docs/QA-RELEASE-CHECKLIST.md](docs/QA-RELEASE-CHECKLIST.md). Keep asset-generated, integrated, verified, released, and production-validated as separate statuses.
- Keep [docs/CURRENT-SPEC.md](docs/CURRENT-SPEC.md) and [docs/EXPERIENCE-DESIGN.md](docs/EXPERIENCE-DESIGN.md) as the living product specification and experience design. For each product PR, update affected sections in the same PR or explain separately why each document is unaffected; follow [docs/SPEC-DESIGN-WORKFLOW.md](docs/SPEC-DESIGN-WORKFLOW.md). Do not satisfy this with date-only edits.
- Current automation is model-gated and available after eligibility; do not restore historical blanket-off flags. Never loosen eligibility, foreground-only execution, save compatibility or quiet handling without tests.

- Read the latest main, open PRs, CI and relevant docs before changing code. Preserve newer changes and never resolve conflicts by blindly taking ours/theirs.
- Implement, run relevant checks, inspect mobile browser screenshots, open a PR, and verify required CI before an authorized merge.
- After merging, remove the disposable head branch promptly. Confirm the PR is actually merged into the default branch, the current head still matches its merged PR head, and no open PR uses the branch as a base or head. Preserve default, protected, release, environment and active branches.
- `.github/workflows/cleanup-merged-branches.yml` performs remote cleanup on merged PR close. Its initial installation/update on main and its manual run sweep older merged PRs. It never checks out PR code; protected/changed/reused branches are skipped.
- When a local checkout exists, switch to updated main, verify there are no uncommitted or unmerged changes, remove the finished local branch, and run `git fetch --prune`. A squash merge alone is not proof that a local branch is disposable; compare its tip with the merged PR's head. Do not force-delete unknown work.
- Include PR/CI status, remaining limitations and branch cleanup results in the completion report.
- Keep the observation UI focused on one large scene. Preserve the existing world and game loop, save compatibility, point accounting, and mobile readability. Unseen records must not reveal their names or images.

- Preserve horror, unease and tension over arcade presentation. Keep patrol/growth rewards understated, avoid combo/speed pressure and celebratory overlays, and leave the scene legible. Put primary controls below content or in the existing lower navigation; never cover text with stamps.
- Do not expose observation tap counts, progress gauges or patrol counters. Keep the title redaction. Observation automation remains hidden/inactive until its model eligibility holds: patrol needs 20 records and two locations; suppression needs 10 manual suppressions and patrol level 1. Preserve saved upgrade levels.
- Anomalies require contact near their image-space target (or the accessible region picker); normal patrol must never suppress them. Contamination grows during active pursuit and recedes with idle time, monitor closure or conversation. Preserve controls, saved progress and offline recovery.
- Keep observation input on the image, without a separate patrol button. Unlock observation settings after training, but keep reduced-motion preferences always available. Fit the scene and rest/conversation controls above the bottom navigation on portrait phone viewports. On short landscape screens, preserve a readable scene and let controls scroll into reach rather than shrinking the scene into a thumbnail. Keep status text outside the image.
- Observation is a self-contained screen: no dispatch, mission CTA or incidental notices below it. Keep those in the task pane. Check document scroll height, not only button visibility, at mobile browser-sized heights. Temporary feedback replaces ambient copy. Content tabs must not overlap images or text while scrolling; list screens may scroll intentionally.
- Connect acquired observation records to saved colleague testimony without revealing unowned records. Keep readings/repeated testimony idempotent for points and recovery, retain explicit monitor resumption, and verify the complete observation → record → witness → comparison flow. Do not equate automated UI checks with proven fear or long-term enjoyment.

- Keep anomaly catalog IDs stable and append-only. Evidence cases must present enough information for one answer, enable/focus explicit completion, and preserve progress on reload. Truth-completion rewards are one-time per acquired dossier, including retroactive claims, without changing duplicate testimony rewards. Prevent gesture zoom on game controls while keeping reading text zoomable.
- Award 1pt per active observation/region input in addition to patrol or suppression bonuses. A missed contact must not advance suppression; opening help, a closed monitor, passive ticks and automation are not taps. Persist the input result and keep the wallet current without per-tap celebratory effects.

- Incursion case IDs are shared by saves, resolved-case discovery and the weighted rarity pool (N/R/SR/SSR = 60/28/10/2; uniform within rarity excluding the immediately previous case). Preserve their meaning. Ordered work, wire isolation, contact and testimony comparison must survive reload; photo misses never advance contact. Keep quiet/keyboard trace alternatives playable, final confirmation explicit and materials idempotent across tiers.

- Observation anomaly chance grows with sensitivity: 5% to 12% in 0.5-point steps (Lv.0–14). Keep held results; migrate existing levels without reducing effects. All four routes are free; legacy route costs are refunded exactly once. No adjacent route repeats. Overall anomaly odds are independent from conditional content weights. Player spillover is cosmetic and event-bound: preserve true controls, wallet, evidence, and save outcomes; no repeated flashes. Quiet disables spillover, reduced motion disables glimpses, and explicit rest calms it.
