# 真相ガチャ 仕様・設計書

対象：`index.html`（v16 相当）。数値・仕様は実装と一致させている。README は概要、本書は設計の詳細。

## 1. 製品定義

- 目的：ガチャを引くこと自体が目的の収集ゲーム。バトル・親愛度などの口実を持たない
- 収集対象：都市伝説・陰謀論（全29件＋機密区分外1件）
- トーン：皮肉・風刺。陰謀論には必ず「判定」判子を付ける
- 中核の仕掛け：同じネタを引くたびに黒塗りが1段剥がれ、5段目（真相）で全貌が分かる
- 方針：Lv5（真相）は意図的にシェアできない形にする（共有不可＝見に行く動機）
- 対象環境：スマホブラウザ最優先。単一HTML、ビルドなし

|---|---|

## 2.5 一般人モード（入門版）

- 目的：SNS経由の新規が、説明なしで触れる超ライト版。通貨・放置・ランクは無し
- 対象：u1, u2, u4, u5, u6, u7, c1, c3, c6, c7, c8, c12。各Lv.3まで、全36断片。1回で必ず1段進む（未発見を1.6倍優先）
- 同封メモ：合計3/6/10/15/18/24/30/36断片で開く。10で閲覧傾向診断、18で異常記録、24で面接招待、30で観察継続、36で完全記録
- 昇格：24断片以降で「調査員になる」→面接3問→`role="agent"`、配属、調査員番号、開始pt+30。読んだ段数は `levels` に引き継ぎ
- 移行：`pulls>0` または `onboarded` の既存データは自動で `agent`
- 一般人は「今日の調査員」の集計に出さない（`scouts` へ書き込まない）

## 3. ゲーム設計

### 3.1 コアループ

疑念pt獲得 → 封筒を引く → 黒塗り解除 → 証拠獲得 → 設備強化 → 放置効率・排出率向上 → 引く量が増える

### 3.2 ネタの構造

- 各ネタ：`id` / 名称 / 区分 / レアリティ / Lv1〜5のテキスト / シリーズ / 任意で `minRank`
- Lv1 噂 → Lv2 発生時期 → Lv3 詳細 → Lv4 信じてる人の特徴 → Lv5 真相
- 区分：都市伝説12、陰謀論12、深層ファイル5（ランク解禁 6/9/12/15/18）、機密区分外1（合計段数35/65/95/120/145で段階開示）
- 事実ベースの陰謀論は裏取り済みの記述のみ（電球カルテル、MKウルトラ、エリア51、トンキン湾、タバコ業界、鳥は実在しない）
- 未発見の名称は黒塗りバーで表示（「???」は使わない）

### 3.3 排出ロジック

1. 引ける候補：箱の区分に一致し、`minRank` を満たすネタ
2. 重み = レアリティ重み × ランク倍率 × 設備倍率 × 進捗重み
   - レアリティ：並1 / 稀0.5 / 禁0.22
   - ランク倍率：稀 ×1.00→1.80、禁 ×1.00→2.80（RANK 1→20 で線形）
   - 進捗重み：Lv0 ×1 / Lv1〜4 ×1.6 / Lv5 ×0.35
3. 天井：未発見が出ない連続回数が上限に達すると、未発見を確定（30→15回、地図で −1/段、最短5回）
4. 5連以上：結果に黒塗り解除が1つもなければ、1件を強制的に解除
5. 二重解除：確率 `0〜20%`（ランク）＋ 除去液 `1%/段` で、解除が2段になる
6. Lv5到達後の重複：目撃証言を獲得（並/稀/禁で証拠 2/5/15）、疑念pt+3

### 3.4 調査員ランク（20段階）

- 累計ガチャ回数で昇格。必要数：`0,10,25,45,75,120,190,290,430,640,950,1400,2100,3000,4400,6500,9600,14000,20500,30000`
- 特典（線形）：放置 +5%/段、稀・禁倍率、二重解除、天井短縮
- バルク解放：10連=RANK 5、100連=RANK 11

### 3.5 経済

| 項目 | 内容 |
|---|---|
| 放置 | 5秒/1pt × 放置倍率 `(1+0.05×rank)×(1+0.1×radio)`。2時台は2倍 |
| 留守中 | 1分/1pt × 倍率。上限 2時間＋留守番電話1時間/段 |
| 嗅ぎ回り | 400ptまで+2/タップ、800ptまで+1、以降0（日次、虫眼鏡で上限+200/段）。12回/秒超は無視 |
| 連続ログイン | 20＋10×min(連続日数,7) |
| 任務（4件・日次） | 嗅ぎ10回=15 / ガチャ3回=20 / 黒塗り2段=25 / シェア1回=15 |
| 本日のウワサ | 日付で決まる1件を1日1回読める（全員共通）。郵便受け演出（連続日数・時刻で文面が変わる）。pt消費なし。「無料」等の表記は使わない（DESIGN §3） |
| 初期値 | 30pt |
| 費用 | 1回10 / 5連45 / 10連90 / 100連850 |

### 3.6 調査室（証拠）

- 証拠入手：新規ファイル3 / 黒塗り解除1（二重+1）/ 目撃証言 2・5・15
- 設備（費用 = `base × grow^Lv`）：

| id | 名称 | 効果 | 最大 | base | grow |
|---|---|---|---|---|---|
| radio | 盗聴ラジオ | 放置 +10%/段 | 20 | 12 | 1.32 |
| phone | 留守番電話 | 留守上限 +1h/段 | 10 | 20 | 1.45 |
| lens | 古い虫眼鏡 | 嗅ぎ上限 +200/段 | 10 | 15 | 1.40 |
| map | 書き込みだらけの地図 | 天井 −1/段 | 5 | 40 | 1.80 |
| fluid | 黒塗り除去液 | 二重 +1%/段 | 10 | 30 | 1.50 |
| card | 情報屋の名刺 | 稀+3% 禁+5%/段 | 10 | 35 | 1.55 |

### 3.7 コレクション要素

- シリーズ7種：全集めで称号、全真相到達で「（真）」
- 目撃証言：時刻・場所・証言者・一言の組合せ（約9万通り、並/稀/禁）
- 信者度診断：収集傾向から6タイプ
- 機密区分外ファイル：合計段数で解禁

## 4. ソーシャル・拡散設計

- シェア種別：色マス（絵文字グリッド）、黒塗りカード画像（canvas）、診断結果
- Lv5の中身は共有物に含めない
- 今日の調査員：同日の参加人数と解読量の順位（要サーバ）
- 調査スレ：匿名掲示板風の固定投稿（クライアント内生成。実ユーザー投稿ではない）

## 5. 演出・UI設計

- 封筒演出：揺れる→開く→せり上がる→黒塗り剥がし。稀=琥珀、禁=赤の脈動。高速モードで短縮
- バルク引き：演出なし、まとめシート表示
- 紙質：都市伝説=罫線メモ（手書きフォント Yomogi）、陰謀論=綴じ穴付き機密書式、黒塗りは墨スタンプ
- 夜間（22〜5時）：赤み＋照明ちらつき。2時台は丑三つ時
- アクセシビリティ：`prefers-reduced-motion` で演出停止
- 日本語改行：`word-break: auto-phrase`＋`text-wrap: balance/pretty`。非対応環境は BudouX（jsDelivr、失敗時は簡易分割）
- フォント：Shippori Mincho / Zen Kaku Gothic New / Courier Prime / Yomogi

## 6. 技術設計

### 6.1 構成

- 単一ファイル（HTML/CSS/JS）。外部依存はフォントと BudouX（CDN）のみ
- 状態は単一オブジェクト `S`。変更のたびに `save()`
- 描画は状態から再生成（`render()`）

### 6.2 状態スキーマ（`localStorage` キー `shinso_gacha_state_v1`）

| フィールド | 型 | 意味 |
|---|---|---|
| currency | number | 疑念pt |
| evi | number | 証拠 |
| pulls | number | 累計ガチャ回数（ランク算出） |
| clicks | number | 累計嗅ぎ回り |
| levels | {id: 0–5} | ネタごとの解除段数 |
| ups | {id: n} | 設備レベル |
| pity | number | 未発見が出ていない連続回数 |
| lastTick | ms | 放置計算の基準時刻 |
| missionDate / missions | string / {id:{p,claimed}} | 任務（日次リセット） |
| freeDate | string | 本日の噂の受取日 |
| sniffDay | {day, pt} | 嗅ぎ回りの日次累計 |
| streak | {…} | 連続ログイン |
| tlog / tcount / tstat / tby | – | 目撃証言の記録・集計 |
| titlesSeen / secretSeen | – | 称号・機密ファイルの既読 |
| onboarded / fast | bool | 初回案内済み / 高速モード |
| role / assign / agentNo | string | `agent`＝調査員。未設定は一般人。配属と調査員番号 |
| lite | {lv:{id:n}, pulls} | 一般人モードで拾った段数 |
| updatedAt | ms | 同期の新旧判定 |

- 読込は `Object.assign(fresh(), saved)`。新フィールドは既定値で補完され、後方互換を保つ
- バージョンキーは据え置き。破壊的変更時は `_v2` と移行処理が必要

### 6.3 クラウド保存・今日の調査員（未稼働）

現状：Artifact 専用 API（`window.claude`）で実装。GitHub Pages では自動無効、端末内保存のみ。
移行先：Firebase。

- 認証：匿名＋Google（匿名からリンクして進捗を引継ぎ）
- Firestore（asia-northeast1）：

| パス | 内容 | 権限 |
|---|---|---|
| `users/{uid}` | `S` 全体（`updatedAt` 付き） | 本人のみ読み書き |
| `scouts/{uid}` | `{day, todayLv, total, lv5}` | 全員読取、本人のみ書込 |

- ルール：`scouts` は `keys().hasOnly(['day','todayLv','total','lv5'])` かつ `total <= 200`
- 競合解決：`updatedAt` の新しい方を採用
- ルールの実体：`firebase/firestore.rules`。手順は `SETUP.md`
- ホスティング：GitHub Pages（`main` / root）。承認済みドメインに `b-w-hiroki.github.io` を追加

## 7. リスク・既知の課題

| 区分 | 内容 | 対応案 |
|---|---|---|
| 公開リポジトリ | Lv5 の本文を含む全テキストが誰でも読める | 許容済み。隠すなら本文をサーバ配信に分離 |
| 不正 | 状態はクライアント保持。`localStorage` 改ざんで全解放可。`scouts` も自己申告 | ルールは上限値のみ。ランキングの厳密性は担保しない |
| 経済 | 証拠が余り、設備が中盤で上限到達 | 設備の最大値拡張、証拠の別用途 |
| コンテンツ | 証言は組合せ生成。数百件で重複が目立つ | 語彙追加 |
| 事実性 | 実在事象の記述は裏取り済みだが、公開前に再確認が必要 | 出典リストの整備 |
| 表示 | 提供割合の表示が未実装 | 一般公開前に実装（景品表示・各ストア規約の確認） |
| 依存 | BudouX は CDN 読込。失敗時は簡易分割に低下 | 許容 |
| 現状 | クラウド保存・今日の調査員が動作しない | §6.3 の Firebase 移行 |
