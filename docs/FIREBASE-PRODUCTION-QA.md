# 本番Firebase・iPhone Safari検収記録（Issue #75）

目的：**コード/エミュレーターの成功と本番環境の成功を分ける**。端末・認証・ルールの証跡を残すまで #75 を完了にしない。

## 0. 自動で検証できる境界

- `tests/cloud-save.cjs`：独立した取引モックでCAS競合、削除中断/再試行。
- `tests/firestore-rules.cjs`：Firestoreエミュレーターで所有者・保存revision・削除済み印・スカウト集計の権限を試験。
- `tests/firestore-multidevice.cjs`：同一UIDの独立クライアント2台をエミュレーターで動かし、競合・削除後の旧端末書込み・直接の復活要求が拒否されることを試験。
- `tests/account-catalog.cjs`：ブラウザでログイン/キャンセル/退会UIを **認証モック**で試験。

以上は本物のGoogle認証画面、Firebase本番ルール適用、実際の2端末接続、物理iPhone Safariを証明しない。

## 1. 本番管理者が先に確認すること（変更前後を記録）

1. Firebase Consoleで**プロジェクトID `shinso-gacha`** と環境を確認。本番をテスト用プロジェクトと取り違えない。
2. Firestore Database → Rules に公開中のルール全文と公開日時を確認し、GitHub `firebase/firestore.rules` の対象main SHAと比較。差分があればレビュー・変更管理を行う。GitHub Pagesの成功だけでは適用済みと判断しない。
3. 必要時のみ認証済みの管理者が `firebase deploy --only firestore:rules --project shinso-gacha` を実行。ユーザーが許可していない本番変更や実ユーザー削除を自動実施しない。
4. Authenticationで匿名・Googleログイン方式、承認済み公開ドメイン（`shinso-gacha.birdman-studio.com`）を確認。
5. 記録：実行者、公開日時、ルールの適用元main SHA、Firebase Console上の公開結果（秘匿情報・APIキー・メールはIssueへ貼らない）。

## 2. テスト用アカウントと端末A/B（実ユーザーは禁止）

前提：**専用テストGoogleアカウント1つ、独立した端末A/B、空のテスト進行**。可能なら別のブラウザセッションでも再現。すべて専用アカウント内で実施し、UID/個人情報を公開Issueに保存しない。

| 手順 | 実操作 | 合格条件 |
| --- | --- | --- |
| T1 | Aで登録なしプレイ → Google連携 → 手動保存 | ゲスト進行・残高・資料IDを保持 |
| T2 | Bで同じテストGoogleアカウントでログイン | Aで保存済みの進行のみ同期。A/Bで資料・装備・ptが一致 |
| T3 | A/Bで異なる状態に進めて順に保存 | revision競合で古い保存は上書きされない。失敗が成功表示にならない |
| T4 | Bを旧状態のまま維持、Aから退会の再認証と削除 | Firestoreの進行は削除済み印だけ、scoutsは削除。Firebase Authenticationの対象ユーザーは削除 |
| T5 | 古いBから保存・再ログイン/再読込 | 古い進行がFirestoreに復活しない。削除済み状態が誤って復元されない |
| T6 | オフライン→再接続／通信失敗時に再確認 | エラー時は確認を出し、退会成功・保存成功を偽装しない |

**注意**：T4以降は不可逆。T1～T3の結果を確認してから、専用テストアカウントにだけ実行する。管理者の承認がない段階では未実施と記録する。
