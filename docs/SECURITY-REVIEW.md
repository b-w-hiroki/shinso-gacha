# 全体コード・セキュリティ点検（2026-10-10）

## 対象
index.html、全ランタイムJS、CSSのサイズ調整、保存・認証、Firestoreルール、GitHub Actions、外部読込、既存テストと公開手順。ゲーム内容・保存ID・得点ルールを保つ範囲で整理した。

## 修正
|優先度|問題|修正・検証|
|---|---|---|
|高|保存された証言・調査員情報をHTMLとして表示|共通HTMLエスケープ。証言ID・希少度を検証し、不明IDでの画面停止を防止。ブラウザで画像タグ混入を検証|
|高|アカウント切替中に旧通信の結果が反映される|読込・保存で接続インスタンスを照合。既存Googleアカウントへの切替前にローカルを退避し、明示的にそのアカウントを読込|
|高|保存ルールが所有者以外の形式を検証しない|state/map・revision/int・許可フィールド・版番号増加をルールで検証。旧版の無条件上書きを拒否。エミュレータで本人/他人/未認証・旧保存の移行を検証|
|中|スクリプト読込元・インライン実行が無制限|CSPで自サイトと必要なFirebase/BudouXを許可。メインスクリプトはSHA256で許可し、inlineイベントを撤去。ハッシュ更新スクリプトとCI整合チェック|
|中|保存データの危険キー・型崩れ|再帰境界でprototype関連キー除去、深さ制限、配列上限、重要な数値・マップ・資料レベル・証言を正規化|
|低|複数ResizeObserverによる同一フレームの再計算|共通フレーム予約処理で各画面の通知を集約。100連続通知が1回にまとまることを検証|
|低|観測報酬処理の二重ローカル保存|markDirty直後の重複saveを除去|

## 残る制約・運用
- Firestoreルールはリポジトリ更新だけでは本番反映されない。Firebase管理権限で別途公開が必要。新クライアント公開後に適用する。旧版タブは保存を拒否されるので再読込が必要。適用前はクライアントの版番号照合のみ。
- 実FirebaseのGoogleポップアップ/既存アカウント切替/2端末同時利用は実アカウントで最終確認が必要。CSPは必要な認証ドメインを許可しているが、この環境の認証テストは代替アダプタ。
- クライアント完結型ゲームのため、本人が自分のptや取得内容を書き換えることを完全には防げない。価値のある報酬や競争ランキングにはサーバー側の判定が必要。公開scoutsは自己申告の範囲制限付き集計として扱う。
- 公開Firebase設定は秘密鍵ではない。サービスアカウント秘密鍵は追加していない。APIキー制限、App Check、予算・使用量通知はFirebase/Google Cloud管理画面で確認する。
- GitHub PagesのHTML内CSPではframe-ancestorsを設定できない。埋込禁止などレスポンスヘッダが必要な対策にはホスティング側の設定が必要。
- CSSのインライン指定は既存画面との互換性のため許可。インラインJavaScriptはハッシュ一致のみ。HTMLメインスクリプト変更時は `node scripts/update-csp.cjs` を実行する。
- CDNライブラリは固定バージョン。外部サービス供給網リスクは残る。依存の大規模更新・単一HTML全分割は今回の修正範囲に含めず、検証済みのゲーム動作を保持した。
- 保存正規化は破損・表示攻撃の緩和であり、全ゲーム状態の厳密なスキーマ検証や改ざん防止ではない。
