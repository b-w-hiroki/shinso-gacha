# 真相からの干渉：異変対処

## 対応タスク

- [x] 調査を進めると異変が蓄積する状態を追加。
- [x] 写真：前後の記録を比較し、増えた人物を照合。
- [x] 通信：送信元不明の回線を選び、遮断。
- [x] 資料：差出人・宛名・本文の順に封印。
- [x] 対処で鎮静し、直後2回の開封を保護。
- [x] 未対処のまま調査を続けると危険度が上昇、100で新規開封だけ一時停止。
- [x] 対処途中・履歴・控えめ演出設定を既存保存に統合。
- [x] スマホ操作・再開・既存ゲーム回帰テストを追加し、ローカルで成功。

## 狙い

調べる対象から逆に観測される感覚と、プレイヤー自身の操作で日常を取り戻す感覚を作る。通常の開封は自動で異変モーダルに割り込まれず、ヘッダーの状態表示から対処に入る。100到達後にさらに開こうとした場合だけ対処画面を開く。収集した資料・疑念ptの没収はない。

## ルール

| 状態 | 表示・挙動 |
| --- | --- |
| 0 | 静穏。対処後は2回の開封を保護 |
| 12–35 | 違和感。以後の調査で増加 |
| 36–69 | 異変発生。写真・通信・封印を順番に循環 |
| 70–99 | 画面端の赤い縁、レーダーの未認証応答 |
| 100 | 新規開封を一時停止。対処・資料閲覧・タブ移動・報酬受取は可能 |

1回の開封で+12、連続開封は個数にかかわらず1操作あたり+20。誤った対処で+6、最大100。解決で0、対処数+1、保護2回。対処によるpt・資料の追加報酬はなく、二重解決でも増えない。時刻・経過時間・アプリを閉じた時間では悪化しない。制限時間・突然の大音量・点滅は追加しない。

新規の「最初の3通」中は蓄積しない。既存ユーザーも過去の開封分は加算せず、導入後に実際に開くところから蓄積する。一般人・調査員の両方で利用でき、異変状態は役割移行後も残る。

## 素材・実装

- `assets/incursions.js`: 状態、開封フック、3種の操作、履歴・保存、ネイティブdialog。
- `assets/incursions.css`: 状態バー、画面端、写真差分、レーダー、回線ランプ、封印、スマホ表示。
- `assets/intro/station-before.webp` / `station-after.webp`: 写真照合とガチャ脇の監視写真の変化。
- `assets/ui/audio-analyzer.webp`: 通信装置の質感。
- `assets/intro/witness-note.webp`: 封印台紙。

既存の写実素材を再利用し、変化する文字・計器・封印と操作部分はHTML/CSSで分離。危険色を本文に重ねない。「演出を控えめにする」で追加の画面端・写真差し替え・レーダー干渉を抑える。危険度と操作案内は残す。

## 保存と検証

`S.incursion` の version / level / resolved / cooldown / event / quiet / history を既存localStorage・Firebase状態に追加。eventは kind / step / seen / view を保存。履歴は最大8件。欠落した旧セーブに後付けでき、値は範囲を正規化する。

`tests/incursions.cjs` で実際の開封、3操作の成功・誤操作・途中再開、連打相当の二重完了、保護区間、100時の全開封経路、320/390/430/1280px、キーボード、設定、保存を検証。Firebaseは既存アダプターをスタブで往復し、実ユーザーのデータには書き込まない。既存smoke/photoreal/dossier-ui/introも実行する。

実画面は `docs/qa-incursions/`、一覧は `overview.jpg`。GitHub Actionsにも異変対処テストを追加。実機Safariと長期的な難易度・離脱率は未測定。
