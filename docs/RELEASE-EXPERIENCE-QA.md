# リリース判定とプレイ体験の未検証項目（2026-10-10）

## 自動検証と実測の区別
- CI合格はロジックと画面操作の回帰を意味し、長時間遊びたくなるか・怖いかの評価ではない。
- 本番Firebaseの権限ルール適用とテスト専用アカウントによる削除・復活防止は必須。権限がない状態で公開完了と扱わない。
- WebKitデスクトップ自動化はiPhone Safari実機の代替ではない。

## 定量的なプレイテスト（ゲスト開始から）
- 初回5分: 最初の有効な操作、初めて封筒を開けるまでの時間、画面移動で迷った回数。
- 30分: 観測地点ごとの出現回数と連続率、異変を初めて発見するまでの時間、取得した異変数、育成レベル、所持pt。
- 60分: 都市伝説の断片収集→証拠→証言→真相候補までの完走数、台詞の重複が気になった回数、離脱したくなったタイミング。
- 翌日復帰: 追跡中案件を自力で見つけられるか、次の行動を選べるか。
- 複数人で実施し、感じた怖さと気づいた異変の時間は分けて記録する。

## P0: 実機・本番環境
1. Firebase Rules反映を管理画面または認証済みCLIで確認。
2. テスト用Googleアカウントと端末2台で同期・競合・ログアウト・再ログイン・アカウント削除を確認。
3. 削除済みUIDの旧セッションから書込できないことを確認。実ユーザーを削除しない。
4. iPhone Safariで320相当・390相当の縦画面と横画面を確認。監視カメラ、写真、視界ジャック、車載カメラを一巡する。
5. 異変の警告バナー、画像内ターゲット、下部ナビ、低刺激設定、視覚効果を確認。

## 実装を変更する際の不変条件
- ガチャの既存提供割合、保存ID、獲得済み資料、pt・報酬を変更しない。
- 未発見の名前・画像・接触位置をDOMへ出さない。
- 恐怖演出は操作の遮断やフラッシュ・音量増加に使わず、低刺激設定・reduced-motionを尊重する。
- 調整はゲーム実測の根拠と変更前後の回帰テストを添えて別PRとする。

## 14日間の自動シミュレーション（人間のプレイテストとは別）

- `node scripts/observation-balance-simulation.cjs` で、80種類の固定シード×14日×1日6回の仮想観測を再現する。観測しなかった時間の見逃しと復帰、保存と再読込、観測後の地点切替、異変の低頻度・育成上限の2条件を区別して計測する。
- `node tests/observation-longterm.cjs` は全ルートの到達、直前の媒体との連続出現回避、取得済み件数とレアリティの整合、オフライン経過中の無報酬、旧セーブの正規化後の継続、および異変確率の大幅な逸脱をCIで検査する。
- 固定したシードに対する確率シミュレーションの値であり、**実際の一人の利用者が初めて異変を見つける時刻や、怖さ・リプレイ意欲・収集の楽しさを実証するデータではない**。実プレイの30分・60分・翌日復帰は引き続き手動で記録する。
- 判定の例：1) 初見プレイヤーが何回で初異変に気づくか、2) 画面上で異変を見つけられたか、3) 本人の恐怖・緊張・納得感、4) もう一度遊びたいか。自動結果と並べて差を分析してからのみ出現確率・演出頻度・育成費用の調整を行う。



### 2026-10-12 再現可能なシミュレーション基準値（PR #133）

80種の固定シード × 14日 × 1日6回の計6,720回を、現行mainの観測モデルで計算した結果です。実際のプレイヤーによる操作・検証人数・継続率ではありません。

| 取得した観測記録 | 6,720 | 6,720 |
| 異変だった記録 | 343（5.10%） | 826（12.29%） |
| 初めての異変までの取得数・中央値 | 13件目 | 4件目 |

| 4媒体の取得数 | 各1,680件 | 各1,680件 |
| 同じ場所のもう一つの映像（奇数seq） | 3,360件 | 3,360件 |

1週間のオフライン経過、セーブ正規化、取得履歴の重複/欠落、既存の低刺激・報酬付与経路をテストしました。記録の見逃し件数はUI上のペナルティと等価ではなく、この結果から楽しさやユーザーの離脱理由を推定しません。初回5分/30分/60分/翌日プレイの実測で **「異変の見た目に気づけるか」「その前に何を理解しているか」** を確認したうえで、確率ではなく演出や発見導線の改善も比較します。


### 異変接触位置ごとの画素差を検査する（PR #134）

`tests/observation-visibility-metrics.cjs` は既存の390×844実ブラウザの写真比較を、画面全体と `WatchLocations.targets(mode,rarity)` の**実際の接触範囲**の両方で行う。12種それぞれに、画像差分が一定値以上の画素割合、平均RGB差、対象楕円内の画素数をJSONへ残す。複数ホットスポットも個別に検査する。通常写真と自身を比較する負の対照でも差分が0であることを検証する。

この数値は描画差の客観的な診断情報に過ぎない。見えやすさ、怖さ、物語への納得感は推定できず、結果を閾値で自動的に「高品質」と認証しない。人物・背景の描き直しを判断する際は、差分領域の局所性と人間の発見時間の両方を確認する。
