# リリース判定とプレイ体験の未検証項目（2026-10-10）

## 自動検証と実測の区別
- CI合格はロジックと画面操作の回帰を意味し、長時間遊びたくなるか・怖いかの評価ではない。
- 本番Firebaseの権限ルール適用とテスト専用アカウントによる削除・復活防止は必須。権限がない状態で公開完了と扱わない。
- WebKitデスクトップ自動化はiPhone Safari実機の代替ではない。

## 定量的なプレイテスト（ゲスト開始から）
- 初回5分: 最初の有効な操作、初めて封筒を開けるまでの時間、画面移動で迷った回数。
- 30分: 観測地点ごとの出現回数と連続率、異変を初めて発見するまでの時間、取得した異変数、育成レベル、所持pt。
- 60分: 都市伝説の断片収集→証拠→証言→真相候補までの完走数、台詞の重複が気になった回数、離脱したくなったタイミング。
- 翌日復帰: 追跡中案件を自力で見つけられるか、次の行動を選べるか。
- 複数人で実施し、感じた怖さと気づいた異変の時間は分けて記録する。

## P0: 実機・本番環境
1. Firebase Rules反映を管理画面または認証済みCLIで確認。
2. テスト用Googleアカウントと端末2台で同期・競合・ログアウト・再ログイン・アカウント削除を確認。
3. 削除済みUIDの旧セッションから書込できないことを確認。実ユーザーを削除しない。
4. iPhone Safariで320相当・390相当の縦画面と横画面を確認。監視カメラ、写真、視界ジャック、車載カメラを一巡する。
5. 異変の警告バナー、画像内ターゲット、下部ナビ、低刺激設定、視覚効果を確認。

## 実装を変更する際の不変条件
- ガチャの既存提供割合、保存ID、獲得済み資料、pt・報酬を変更しない。
- 未発見の名前・画像・接触位置をDOMへ出さない。
- 恐怖演出は操作の遮断やフラッシュ・音量増加に使わず、低刺激設定・reduced-motionを尊重する。
- 調整はゲーム実測の根拠と変更前後の回帰テストを添えて別PRとする。
