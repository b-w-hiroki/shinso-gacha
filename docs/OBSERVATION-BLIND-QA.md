# 観測の人間ブラインド検収（16画像）

## 目的

自動画像差分・Firestoreテストだけでは「異変を見つけられる」「怖い」を証明できません。実際の利用者が16件の観測素材（4地点×平常1＋異変3）を**正解ラベルなし**で確認するため、独立したQAページ `/qa/observation-blind.html` を設置します。

一般人編・調査員編、ログイン、抽選、所持pt、図鑑、プレイヤーデータにはアクセスしません。進行・回答はメモリ内のみで、ブラウザを閉じると消えます。送信サーバー・分析SDK・識別子はありません。自分で「匿名JSONを保存」を押した場合だけ、回答内容が手元に出力されます。公開Issueには氏名/識別情報を貼り付けないでください。

## 使い方

1. 自分のスマホから同ページを開く（またはローカルHTTPサーバーで `qa/observation-blind.html` を開く）。同じ条件で実施するため、縦画面・端末の明るさ・低刺激設定を統一する。
2. 「検収を開始」から16枚をランダムな順番で観察する。違和感を見つけたらその場所をタップ。ないと思えば「異変は見つからない」、確信できなければ「判断できない」。
3. 途中に正解・レア度・異変場所を見せず、結果と報酬をフィードバックしない。取得済み情報があるテスターは「以前に見たことがある」と別途申告する。
4. 16枚終了後、主観（不気味さ／分かりやすさ／また調べたさ、各1〜5）を任意入力し「匿名JSONを保存」。各尺度の1と5には意味を表示し、中間値はその間として選ぶ。各回答は表示までのミリ秒、タップ画像内座標、正誤区分を含む。
5. 複数人の結果を個人識別しない形で比較する。**初回の正しい発見までの中央値、見逃し、誤タップ、見つからない選択、主観**を別々に解釈し、特に暗い夜道R/SSR・踏切SRを優先して判断する。

## 現在の限界

- このQAページは**画像の静止状態1倍**で、元写真＋写真由来WebP差分＋SVG手掛かりを表示します。実ゲームのモニター周囲のノイズや2倍パン操作、動き・報酬・翌日再訪は測りません。
- 正しい異変位置は `WatchLocations.targets` の楕円領域で判定します。時間切れは強制しません。「見つからない」は見逃しとして残します。スマホでの誤操作と発見の失敗を混同せず解釈します。
- 16枚の順番はその実施ごとにランダムで、どのモード/レア度が先に出たかは**出力後**のJSONで初めて確認できます。人間の知覚を機械のpixel deltaだけで代理評価してはいけません。
- 現行CI `tests/observation-blind.cjs` は16画像のデコード・実座標タップ・無保存と結果JSON・320/390/844pxのブラウザ品質のみを確認します。**人間による実測値はまだ収集されていない**ので、これを人間の検収合格と扱いません。
- 本番Firebaseと物理iPhone実機Safari、異変画像12点の材質・光源整合、長時間の継続プレイは引き続き Issue #75・#89 で管理します。

## 出力スキーマ

`shinso-observation-blind-qa-v1`。セッション内16行の `mode`（4媒体）、`rarity`（0〜3）、`response`（tap/none/skip）、`point`（0〜1の画像内座標）、`result`（hit/correct-normal/false-positive/missed/skip）、`elapsedMs`（提示から回答まで）に加え、件数・発見時間中央値と任意の3主観評価を記録します。氏名、メール、アカウント識別子、位置情報、所持ptは記録しません。
