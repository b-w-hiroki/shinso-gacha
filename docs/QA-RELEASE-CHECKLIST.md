# QA・リリース判定チェックリスト

基準：2026-10-11。判定単位はPR・main・公開環境。自動CI、実ブラウザ、実機、本番環境、人間の体験評価を混ぜて「全確認」としない。

## 1. 受入条件のレベル

| レベル | 判定の内容 | 証拠 |
| --- | --- | --- |
| L1 構造 | ファイル・静的チェック・ID・スキーマ整合 | nodeテスト、ドキュメントチェック |
| L2 機能 | 通常/境界/失敗/保存時に操作が正しい | モデル/ブラウザテストのログ |
| L3 表示 | 実レンダリングで読める/重ならない/画像が一致 | スクリーンショットと目視レビュー |
| L4 実機 | iOS Safari等でタッチ・スクロール・復帰が動く | 端末/OS/再現手順/画面画像 |
| L5 本番 | GitHub Pages・Firebaseが実際に公開/同期/削除できる | 管理者確認・テスト用アカウント |
| L6 ゲーム性 | 怖いか・反復したくなるか・気づけるか | 人間によるプレイテストと指標 |

**CI全緑はL1～L3の一部。L4～L6を自動的に保証しない。**

## 2. PRの必須テスト群

既存の \`.github/workflows/smoke.yml\` を継続する。

| ジョブ | 主な検証 |
| --- | --- |
| smoke | JS/HTMLの基本契約、ガチャ・観測モデル、レアリティ、証言/人事、保存、安全、CSP一致 |
| browser | Playwright Chromium。320/390/430/横等で導入、観測、異変100種類、課員、図鑑、アカウント、レイアウト |
| webkit | Playwright WebKit。人物・記録・侵入、quiet/演出軽減、iOSに近いブラウザーエンジン |
| security-rules | Firebase Firestoreエミュレーターでの権限・削除済み印と、実トランザクション2端末競合・削除後復活拒否 |
| screenshots/artifacts | QA出力の画像・結果JSON。PRのコード差分と一緒にレビュー |

代表的な実行：\`node tests/smoke.mjs\`、\`node tests/observation-model.cjs\`、\`node tests/intro.cjs\`、\`node tests/personnel-discrepancies.cjs\`、\`node tests/account-catalog.cjs\`。ブラウザテストはPlaywrightとブラウザ・日本語フォントが必要。実行できない環境ではCI結果を根拠にし、**ローカル実行したと偽らない**。

## 3. 画面・ユーザー行動のチェック

- [ ] 320×568、390×844、430×932、844×390（短い横）の主要操作が届く。
- [ ] 固定フッター・ヘッダー・モーダルが本文やCTAを隠さない。
- [ ] 本文の行間とコントラストが読める。日本語の不自然な1文字改行がない。
- [ ] 初回3通の写真がロードされ、同じ場所のbefore/afterを比較できる。
- [ ] 3/6/10断片のナビ解放、36断片の事情聴取、スキップの進行非付与。
- [ ] 観測の画像上のタップ、3×3位置選択、通常時の誤鎮静の防止。
- [ ] 休息・会話・資料へ移ると回線の状態が分かる。無操作で勝手に危険にならない。
- [ ] 画像、説明文、枠、ボタン縁、視線の誘導が現行モックと一致する。
- [ ] quiet / reduced-motion / フォーカス / スクリーンリーダー / Escapeや戻る操作。
- [ ] 図鑑は発見済みの名称だけを表示。未獲得の正解・結論・画像をDOMに出さない。

## 4. 保存・ゲーム経済のチェック

- [ ] 古い \`shinso_gacha_state_v1\` を読める。モデルversionの移行を含む。
- [ ] 取得済み事件ID、観測記録、証言、装備Lv、ptが欠落しない。
- [ ] 再読・モーダル再開・多重タップ・再読込で報酬が重複しない。
- [ ] 事件の途中手順・確定済み抽選は再開後も保持。
- [ ] 日付境界、長期不在、時間逆行、非表示タブ、低刺激設定が破綻しない。
- [ ] 自動化と手動入力は同じモデルの保存意味を維持。バックグラウンドに大量の疑似タップを足さない。
- [ ] 高ランク証言・機密は閾値前に見えない。課員から得た証言は同じものを再付与しない。
- [ ] 誤った回答や異常レベル100でも資料/所持ptを没収しない。
- [ ] Firebase競合、ログアウト、削除中、権限拒否で成功表示を出さない。

## 5. イベント・ホラーの検収

- [ ] 平常が理解でき、違和感の場所が発見可能。
- [ ] 状態差分が単なる別絵になっていない。
- [ ] 演出と真のボタン操作を混同しない。点滅・大きな揺れ・意味のない赤ノイズを増やさない。
- [ ] 課員の肖像と誰の発言かが明確。誤認させるのは物語上の内容であってUIではない。
- [ ] 侵入事件のレアリティ N/R/SR/SSR=60/28/10/2 とID互換を維持。
- [ ] 画像のタップ位置が異常の実体に対応する。
- [ ] 「発見」と「正解の確定」が別。結論を先に明かさない。

## 2026-10-15 WebKit SSR再発率の継続観測（#141）

- [`.github/workflows/webkit-ssr-stability.yml`](../.github/workflows/webkit-ssr-stability.yml) は毎日・手動起動・対象テスト変更PRで、以前にクラッシュした写真／車載のSSRをWebKitの独立プロセスで反復する。
- 各媒体で実クリック暗部補正・拡大を3回、通常/R/SR/SSR＋SSR追加3回の計7画像試験を毎回実施。失敗を同一run内のリトライで成功にせず、最初の失敗をrun失敗として残す。
- `webkit-stability-photo` と `webkit-stability-dash` のartifactにmain SHAと試行ログを30日保持。`results.json` は媒体ごとに暗部補正3回＋映像7回（SSR4回）の計10件を、個々の成功・失敗・終了コード・所要時間とともに記録する。途中の1件が失敗しても残りの実行を続け、最終ジョブは必ず失敗扱いにする（成功への再試行はしない）。判定時は連続runの**初回成功数／試行run数**と、対象媒体・具体的失敗ステップを記録する。リトライ後の成功だけを安定化の根拠にしない。
- GitHub Actionsの定期実行成功は物理iPhone Safariの実機成功を意味しない。#75 の検収と区別し、#141は必要な証拠が揃うまでOPEN。

### SSR合成素材のQA（#141）

- `tests/ssr-composite-asset-audit.cjs` は4媒体SSRの画像バイナリ、元写真・WebP・SVGのSHA256、1440×720の寸法と安定したファイル名を検査する。生成済みZIPだけを公開成功とみなさない。
- 実ブラウザではSSR前景1層・R/SR前景3層と画像中心の実タップ/保存・縮小時の見切れを確認する。WebKitの写真/車載の専用10試行は失敗をそのまま保管し、テストをスキップせず再発率を記録する。
- 合成前後の画素差/主観評価は機械だけでは証明できず、iPhone Safari実機とブラインド発見率の検収は #75/#89 のOPEN条件とする。

## 6. GitHubと公開判定

\`\`\`text
PRのhead固定 → 各CI成功 → ブラウザartifact目視
           → レビュアー承認相当の差分確認
           → merge → main SHA確認
           → Pages配信の更新確認
           → (必要な場合) Firebase Rules/認証を管理者が先に反映
           → 本番テストアカウントで同期/削除
\`\`\`

- [ ] 一括 \`ours/theirs\` 採用をせず、最新mainと差分が整合。
- [ ] HTMLインラインJS変更時の \`scripts/update-csp.cjs --check\` 成功。
- [ ] PRのファイル一覧に大きな意図外変更、素材消失、CIスキップがない。
- [ ] CIに失敗や未完のジョブがない。UIテストが失敗したままマージしない。
- [ ] 画像バイナリのGitHub反映が確認できる（生成先のZIPだけでは不可）。
- [ ] Pagesの配信が新mainの内容と一致（本番のハッシュや目視で確かめる）。
- [ ] 使い捨てブランチを削除。ただし再利用中・未統合・保護対象のブランチは消さない。

## 7. P0: 本番・実機でまだ必要なこと

1. 本番Firebaseで \`firebase/firestore.rules\` が適用されているか、管理者が確認する。
2. テスト専用Googleアカウント2端末で、初回連携→同期→ログアウト→再ログイン→競合→削除→古い端末からの復活拒否を検証。
3. iPhone実機のSafariで縦・横、タップ、画像比較、異変ターゲット、下部ナビ、低刺激設定、スクロール・復帰を検証。
4. 100事件のID・バイナリ、追加観測地点の品質を追跡。生成済み素材を公開済みと混同しない。
5. 第0章初回体験と翌日再訪を複数人で確認。脱落率・恐怖・理解・再訪を分けて記録する。

## 8. ゲーム性の記録テンプレート

\`\`\`md
### プレイ条件
端末/OS/ブラウザ、テスト版SHA、一般人 or 調査員、経過時間
### 行動ログ
封筒数、観測数、初異変までの時間、異変発見と対処、休息、再読、離脱箇所
### 主観（各1〜5）
不気味さ / 緊張 / 分かりやすさ / 繰り返したさ / 読み疲れ
### 自由記述
初めて違和感に気づいた瞬間 / 意味の分からなかった操作 / もう一度見たい資料
### 変更判断
具体的な画面・演出変更、効果予測、測定方法、次回の比較対象
\`\`\`

証跡を伴わない「良くなった」「怖くなった」は検証済み事実として扱わない。
